# طالب | Tâlib — v0.1 (النسخة الرسمية المتصلة بـ Supabase)

هذه نسخة **حرفية** من وثيقة التسليم التنفيذية (GLM-5.2)، مستخرجة ومنظّمة بدون أي تعديل على الكود، حسب توجيه الوثيقة نفسها: *"أنشئ الملفات حرفيًا كما في الملاحق — لا تحسّن الكود ولا تعيد هيكلته في هذه الجولة."*

## ⚠️ ملاحظة أمان مهمة
هذا المشروع يحتوي على **مفتاح anon الحقيقي لمشروع Supabase الخاص بك** في `lib/core/supabase_config.dart`. هذا طبيعي ومقصود (المفتاح عام بالتصميم وتحميه قواعد RLS)، لكن:
- **لا تشارك هذا الملف أو الأرشيف علنًا** (مثلاً في مستودع GitHub عام) دون انتباه.
- **لا تضع مفتاح `service_role` أبدًا** في أي كود — هذا المفتاح له صلاحيات كاملة على القاعدة ولم يُدرج هنا أصلاً.

## خطوات التشغيل بالترتيب

### 1) قاعدة البيانات (مرة واحدة)
افتح لوحة Supabase الخاصة بمشروعك → **SQL Editor** → **New query** → الصق محتوى `supabase/migrations/0001_init.sql` كاملًا → **Run**.

تحقق بعدها بتنفيذ:
```sql
select count(*) from institutions;   -- يجب أن تكون 1
select count(*) from courses;        -- يجب أن تكون 6
select count(*) from schedules;      -- يجب أن تكون 12
```

### 2) إعدادات المصادقة
في لوحة Supabase → **Authentication → Providers**:
- فعّل **Anonymous** (يشغّل زر "المتابعة كزائر")
- في **Email**: أوقف خيار **Confirm email** (لتجربة فورية بلا انتظار بريد)

### 3) تشغيل تطبيق Flutter
```bash
flutter pub get
flutter run -d chrome
```
(التشغيل الأول يحتاج إنترنت لتحميل خط IBM Plex Sans Arabic عبر google_fonts)

### 4) بعد أول تسجيل دخول لك — ترقية حسابك إلى admin
في SQL Editor، بعد تسجيل الدخول ببريدك مرة واحدة على الأقل:
```sql
update public.profiles set role = 'admin'
where id = (select id from auth.users where email = 'بريدك@هنا.com');
```

## القرارات النهائية المحسومة في هذه الوثيقة
| البند | القرار |
|---|---|
| Backend | **Supabase نهائيًا** (لا Firebase) |
| إدارة الحالة | Riverpod + GoRouter لاحقًا — غيابهما في v0.1 مقصود |
| الأدوار | طالب + مشرف فقط في MVP |
| البحث | إجراء أعلى الشاشة، ليس تبويبًا سفليًا |
| التنقل السفلي | 5 تبويبات: الرئيسية، المقررات، الجدول، ملفاتي، المزيد |
| وحدة التنظيم | الأسبوع |

## ⚠️ تنبيه مهم بخصوص عملي السابق في هذه المحادثة
بنيت لك سابقًا مشروع `talib_app` بواجهات كاملة (13 شاشة) لكن ببيانات وهمية بدون اتصال حقيقي بـ Supabase. **هذا المشروع (`talib`) مختلف تمامًا**: بنية أبسط (شاشتان فقط: دخول وإعداد وشاشة رئيسية بسيطة) لكنه **متصل فعليًا بقاعدة بيانات حقيقية**. الأفضل أن تقرر أي اتجاه تريد أن نكمل عليه.
